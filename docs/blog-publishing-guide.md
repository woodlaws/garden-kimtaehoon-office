# 네이버 원문을 홈페이지 글로 재구성하는 방법

첫 적용 글: `/blog/liquor-import-trade-number`

1. 김태훈 행정사의 원문을 읽고 제목, 작성일, 핵심 사실과 사진 순서를 확인합니다. 성공사례와 일반 절차 안내를 구분하며 없는 수행 결과를 만들지 않습니다.
2. 독자가 궁금해하는 순서로 제목·도입·소제목·요약·FAQ·상담 안내를 새로 작성합니다. 신청요건·기간·기관 안내는 공식 자료와 대조합니다. 오래된 화면은 촬영/원문 시점을 설명합니다.
3. 공개가 허용된 원문 이미지를 `public/images/blog/<slug>/`에 저장합니다. 네이버 외부 이미지 URL을 직접 연결하지 않습니다. 문서 속 개인정보를 확인하고 민감정보가 있으면 공개본에서 제외하거나 별도 비식별 처리를 거칩니다. 새 이미지로 실제 사례를 만들어내지 않습니다.
4. `data/blog/`에 `BlogPost` 형식으로 글을 추가하고 `data/site.ts`의 `blogPosts`에 등록합니다. `source`, `references`, 이미지 `alt`·`caption`·실제 크기를 작성하고 `docs/blog-source-<slug>.json`에 출처를 남깁니다. 글별 체크리스트와 FAQ를 사용합니다.
5. `pnpm build` 후 목록·분류·검색·본문·이미지 확대·상담 링크·sitemap·RSS를 확인합니다. 발행일은 홈페이지 게시일로 기록하며 원문 작성일을 별도로 표시합니다.

본문·이미지·참고자료는 서버에서 렌더링됩니다. 블로그 목록에는 검색과 카드에 필요한 정보만 전달합니다. 원문 기반 글은 `BlogPosting` 구조화 데이터에 원문과 공식 참고자료를 연결합니다. 이 구성은 검색엔진의 이해를 돕지만 AI 검색 인용이나 순위를 보장하지 않습니다.
